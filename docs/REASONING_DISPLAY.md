# 模型思考展示与调试记录

思维链展示、深度思考开关与独立调试记录。源自 `feat/reasoning-display`（基于空间分支 `851e2cb9`），按用户要求合入 `master`；搜索和文件输入另行实现。

## 游戏设置

“游戏设置 → 游戏偏好 → 显示思维链”默认关闭，在本机保存并立即生效。界面展示接口实际返回的 reasoning_content，使用独立可折叠面板，不拼进守秘人正文、行动选项或玩家消息。关闭立即清空临时展示；生成中途开启，从下一个思考片段开始展示，不补回关闭时的内容。

本设置不改变模型请求的 thinking 参数，也不额外调用模型。没有返回思考内容的模型只显示等待说明，不伪造思维链。经典 DeepSeek Flash 的 auto 策略可能显式关闭思考；已有 TRPG_STORY_THINKING=enabled/provider 可调整经典请求行为。结构化 DeepSeek 决策调用在默认模式下仍关闭 thinking；用户显式开启时遵从保存的模式，输出预算耗尽仍会暂停，不把推理文本当作决策正文。

经典流式请求边接收边展示；结构化主持的非流式调用在收到响应后展示其中实际返回的思考内容。每个请求展示最多 65536 字符级别的内容，最多保留最近 8 条；切换世界、断线、关闭展示或开始新经典回合会清空。面板不抢输入焦点，片段更新只滚动其内部文本区域。

## 权限与历史

本地单人连接可查看；云端单人仅房主，多人房间仅具有 can_keeper 的成员。多人房主身份本身不授予主持秘密。房间投递按当前成员权限逐批过滤，思考内容不进入公开广播或回放缓存。

传输类型为临时 model_reasoning，包含 start/delta/end、request_id、model、role，可附 world_id、turn_id；分块大小兼顾浏览器 UTF-16 长度校验。走独立回调出口，不写回合事件、存档、聊天历史、EventOutbox 或普通诊断正文。SDK 工具链所需的完整推理回传仍保持原样。

## 独立调试日志

按本次用户要求，模型返回的思考内容默认记录在日志目录的 reasoning-debug.jsonl，与 trpg.log、diagnostics.jsonl 分开。界面开关不控制调试记录。

目录沿现有日志优先级：TRPG_LOG_DIR；TRPG_RUNTIME_ROOT/logs；打包程序旁 logs；源码默认仓库父目录 mid_product/<仓库目录名>/work/runtime-logs。桌面正常使用 Electron 用户数据目录中的 runtime/logs。

每条 JSON 含 UTC 时间、世界、模组、经典回合 ID（若有）、请求编号、结构化触发请求（若有）、模型、角色、状态、脱敏文本长度与 SHA256。单条文本最多 65536 字符，记录截断标记；文件按 5 MiB 轮转，保留 3 个备份，创建权限 0600。凭据按现有日志脱敏规则过滤，跨模型分块的 Key 也在整段落盘时过滤。写入失败不改变游戏结果。

关闭思考调试记录：TRPG_REASONING_DEBUG=0。全局 TRPG_DIAGNOSTICS=0 或 TRPG_DIAGNOSTIC_CONTENT=0 也会禁用该内容记录。日志可能包含剧情秘密，只在本机排障，不加入玩家公共日志或自动分享。

## 本批验证边界

只使用离线模型桩、直接受影响的组件/协议测试及本地隔离 UI 检查；不逐项运行全量，不调用真实模型、搜索或文件服务，不测试生产。本地截图检查 1280/939/640 宽度的设置与思考面板，并验证展示开关和输入焦点。原始过程记录在仓库外，最终结果见 docs/INDEX.md 对应归档。

## 开启深度思考

游戏偏好的“开启深度思考”与“显示思维链”分开：前者真实发送 DeepSeek 的 thinking enabled/disabled，后者只控制临时界面。未设置时保留旧 auto 策略（DeepSeek Flash 常规叙述关闭）；不开启显示也可以让模型思考。

思考模式保存到当前模型配置，本地、账号/单人世界、多人房间沿用现有作用域；多人仅房主可写，成员只读。修改从下一回合生效，同回合工具调用使用冻结值；结构化主持从下一次模型决策使用新值。切换不会提交尚未保存的服务草稿，也不会替换 Key。旧配置缺少 thinking_mode 时按 auto 兼容。

目前该开关支持 DeepSeek，其他厂商不发送 DeepSeek 专属参数。开启可能增加等待和 token 用量；预算仍尊重原有最大输出设置。达到预算上限或正文为空时沿现有错误/暂停流程处理，不因切换模式额外发起探针调用；错误沿现有重试/暂停策略处理。

DeepSeek 工具请求的 reasoning_content 在现有会话内按调用 ID/正文摘要保管，覆盖仅返回文字的 assistant。只放到 SDK wire 副本；旧非思考历史和重启后无可用推理的历史使用空字段，不伪造内容，不从调试文件还原。原始思考仍不写入聊天/存档。接口规范依据：[DeepSeek Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/)。
