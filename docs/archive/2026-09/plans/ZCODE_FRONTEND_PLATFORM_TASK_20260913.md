# 给 zcode：前端结构化操作与主持台执行提示词

> 历史归档（2026-09-16 整理）：正文保留当时的结论与适用版本，不作为当前完成状态或执行授权。现行入口见 [README](../../../../README.md)，未完成事项见 [STATUS](../../../STATUS.md)。正文中的仓库路径按仓库根目录理解，`/tmp` 产物不保证仍存在。

```text
请在实验分支实现“结构化操作跑团平台”的前端部分。
完整规格：`STRUCTURED_PLAY_PLATFORM_PLAN_20260913.md`。
补充背景：docs/KEEPER_PLATFORM_HARNESS_DESIGN_20260913.md。
先完整阅读主规格与 AGENTS.md，检查工作区已有场景指示器等改动，
保留他人成果。你负责 frontend/ 和前端验收，Kimi 负责后端与协议。

本次不是仅画 UI：要让按钮提交明确操作、接收主持处理结果，
并完成人类主持无模型流程。不要继续调用
sendAction(buildPanelActionText(draft)) 作为新模式权威入口。

先获取 Kimi 的 M0 schema、错误码、能力协商和 fixtures；以它们
生成/维护 TypeScript 类型和校验。可用 fixture 提前开发组件，
但不能自创不兼容 API，也不能把 mock 演示冒充完成联调。

实现内容：
1. 线索卡保留分类/折叠，出示编辑器支持说明内容、展示图片、
   展示原件；选择合法目标 ID，可选询问。出示不等于转交或消耗。
2. 道具使用带物品 ID、数量、操作和目标，支持文字补充即兴做法，
   不在前端扣数量，不靠标签识别实体。
3. 左上角复用现有当前场景显示，提供“前往…”入口；只展示服务端
   公开目的地，只有已提交场景事件更新位置。
4. 新增普通“掷骰”面板与持久 CheckRequestCard；指定玩家点击
   “掷骰/放弃”，其他人只读。参数由服务端检定请求决定。
   骰子动画使用服务端结果，失败回退文字，不能随机第二次。
5. ActionStatusCard 显示处理中、等待回应、完成/拒绝/暂停；
   服务器接收不等于行动成功。失效目标与冲突有明确反馈。
6. 提交超时查询原请求或同 ID 重试；草稿保留；刷新恢复待检定；
   切世界清理绑定，旧事件不污染新世界。
7. 最小 KeeperConsole：人类可查看授权模组资料、选择 NPC 发言、
   私发线索/图片、请求检定、处理玩家意图、调整 HP/SAN、移动、
   推进时间及保存续团。房主不自动等于 keeper，主持不必认领角色。
8. 本地、云端单人和多人均暴露相应模式和按钮，human 不被模型
   设置门禁挡住。保持旧模式兼容；协议不支持时明确提示，
   不静默退回自然语言发送。
9. 接入 assisted 草稿批准/拒绝、Agent 暂停/接管反馈，按阶段
   依赖后端完成。不在 UI 假装已有未实现的服务能力。

ws.ts/room-ws.ts 复用统一事件处理与传输适配，按 world、event_id、
sequence/revision 处理；同 revision 的不同聊天事件不能全部丢弃。
新结构消息按明确 speaker 渲染，不分析正文猜发言人。
沿用现有主题、角色面板、骰子动画与布局；按适用技能检查按钮。
验证桌面、窄屏、长名称、键盘操作、禁用原因和错误后草稿保留。

先组件/状态/协议测试，再接真实本地后端做多客户端 E2E：
一位人类主持、两位玩家、无 Key/无模型完成法伦→停尸房调查，
包括一次私发、一次检定、SAN、存档与重连。
记录实际 outgoing payload，证明按钮传的是结构请求。
本地和云端模式路径均需验收；不要到生产环境测试。

交付：文件清单、契约版本、测试与构建结果、实际界面截图/录屏、
联调证据与剩余缺口。不改后端来绕过授权或伪造成功，不自动发布。
完整完成前端阶段与联合验收，不把静态原型当作最终交付。
```
