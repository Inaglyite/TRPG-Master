# 游戏内“当前所在场景”显示（P1）

> 历史归档（2026-09-16 整理）：正文保留当时的结论与适用版本，不作为当前完成状态或执行授权。现行入口见 [README](../../../../README.md)，未完成事项见 [STATUS](../../../STATUS.md)。正文中的仓库路径按仓库根目录理解，`/tmp` 产物不保证仍存在。

日期：2026-09-13。范围：只做顶栏的“当前场景”一行及其必要的数据同步，不做主持台
或平台重构（设计参考 `docs/archive/2026-09/plans/KEEPER_PLATFORM_HARNESS_DESIGN_20260913.md` 第 7.1 节）。

## 1. 效果

开局后，模组标题下方持续显示一行：

> 猩红文档
> 当前场景 · 密斯卡托尼克大学医学院

只展示文本：没有地图、没有弹窗、没有场景跳转按钮。本地桌面、云端单人、云端多人
共用同一个组件（`AppHeader` 是三种模式公用的顶栏组件）。

## 2. 数据契约：一份权威，一个投影

位置只有一份权威来源：世界状态里的 `current_scene`，由引擎在移动被提交时写入
（`GameEngine._resolve_scene_transition` 通过 `state_set current_scene.id` 落库），
以及模组初始状态。没有第二份可写的位置状态，前端也不缓存位置到 localStorage。

新增 `src/gameplay/scene_projection.py` 只做派生：

| 输入 | 输出 |
|---|---|
| 权威世界状态 | `{"name": <玩家可见地点名>} \| null` |

派生规则刻意保持窄：

- 只输出地名。场景 `id`、`description`、`exits`、`npcs_present`、`document` 一律
  不出境，因此场景 id、幕后描述、在场人物不会通过这条链路泄露。
- 展示名优先取作者声明的玩家可见名（场景 `public_name`，模组可通过既有
  `extensions` 机制写入，编译器会把它合并到场景顶层），没有才退回场景 `name`。
  世界内取值优先于模组目录；目录里的值让旧存档在模组刷新后也能立刻拿到玩家名，
  不需要移动一次或重开。
- 场景名等于场景 id 时视为“没有可用名称”（老加载器缺 `name` 时会写成 id），
  返回 `null`，前端显示“位置未知”，而不是把那串内部键显示出来。
- 不做正文解析、不做关键词匹配、不读历史小说文本。玩家提到地名、点击“前往”
  选项、模型写到别处，都不会改变这一行。

## 3. 协议：复用既有玩家状态通道

不新增消息类型（旧客户端因此不需要改动就能继续工作，只是不显示这一行）：

| 消息 | 新增字段 | 覆盖场景 |
|---|---|---|
| `world_context`（本地） | `scene` | 首连、换模组、换时间线、建分支 |
| `state_data`（本地 + 云端） | `world_id`、`scene` | 开局、每回合 `done` 后、读档、换时间线后的补拉 |
| `room_full_state`（云端） | `world_id`、`scene` | 房间首连与断线重连的个性化镜像 |

`scene` 为 `null` 表示服务端确认“现在没有可用位置”（前端显示“位置未知”）；
字段缺失（旧服务端）表示“这次没有新信息”（前端保持现状）。

云端两条路径都是按成员定向发送的：`messages.py` 的 `state` 分支用成员自己的
socket，`recovery.py` 的镜像同样只发给请求者，不会把位置广播给其他成员之外的
额外数据（镜像本身本来就只有公共历史 + 该成员私有状态）。

## 4. 前端行为

新建 `frontend/src/state/scene-store.ts`，只有三件事：

- `setWorld(worldId)`：世界标识变化时立刻清空并进入 `syncing`（显示“正在同步
  位置…”），标识未变则不动，避免同一世界的重复同步抖动。
- `applyScene(worldId, scene)`：世界不匹配就丢弃（旧世界迟到事件不会写到新世界
  的标题上）；`scene` 缺失时保持现状；`null` 或空名进入 `unknown`。
- `sceneLabel()`：`syncing` → “正在同步位置…”，`unknown` → “位置未知”，
  否则显示地名。

接线点：

- `ws.ts`：`rememberWorld` 现在同时 `setWorld`；`world_context`、`state_data`
  两个分支应用投影。`state_data` 只在回合外应用（与角色面板同一时序判断），
  正文还在播出发描写时标题不会跟着叙述跑。
- `ws.ts` 的 `loaded`：读档成功后立刻补拉一次权威状态。续团回合的模型响应可能
  要几秒，这样位置在等待期间就已经落到存档里的地点。
- `room-ws.ts`：`connectRoom` 先清空；`room_full_state` 应用世界标识与投影。
- `AppHeader.tsx`：`gameStarted` 为真时渲染这一行（沿用开局/回大厅的既有语义），
  `title`/`aria-label` 承载完整地名。

## 5. 布局

- 桌面：`.header-leading` 是纵向排列（标题 → 当前场景 → 云端“离开冒险”），
  位置行与标题文字左缘对齐，`max-width: min(38vw, 420px)` 单行省略。
- 窄屏（≤520px）：顶栏改为两行 —— 位置行独占第一行，工具栏整行铺开在第二行。
  这样位置行不会挤压按钮；工具栏按钮改按可用宽度均分（原来是忽略间距的
  `(100vw - 40px)/6`，本来就会溢出约 3px）。
- 超长地名：CSS 省略号 + `title`/`aria-label` 提供完整名称。

## 6. 验收

后端（`tests/test_scene_projection.py`，17 例）：

- 只输出 `name`；描述/出口/在场人物/id 不出境。
- 场景名等于 id → `null`；缺场景/空名 → `null`（不猜）。
- `public_name` 优先级：世界内 > 目录 > 场景 `name`。
- 本地 WebSocket：首连 `module_list` 带世界标识，`state_data` 带 `world_id` +
  `scene`；重复查询位置不变；提交移动后更新；换成非法场景名时回到“未知”。
- 换模组时 `world_context` 重新下发权威场景。
- 云端：房间 `state` 请求与 `room_full_state` 都带投影；世界存储不可用时为 `null`。

前端（20 例：`scene-store.test.ts`、`scene-sync.test.ts`、
`AppHeader.scene.test.tsx`）：

- 状态机：同步中/已知/未知、缺字段不动、切世界清空、旧世界迟到事件被丢弃。
- 顶栏：开局前不显示、开局后显示在标题下方、超长名有 `title`、不新增任何入口。

e2e（`frontend/e2e/scene-indicator.spec.ts`，真实后端 + 模型桩）：

- 开局前无这一行；开局显示“当前场景 · 密斯卡托尼克大学”。
- 直接提交一次权威世界状态变更（模型桩回的正文与地名无关）后，位置更新为
  “当前场景 · 密斯卡托尼克大学医学院”，证明位置来自已结算状态而不是正文。
- 长地名在 1280/939/760/640/560/520/430/390 八个宽度下都可见、不超出视口、
  不与工具栏重叠，按钮仍有可见宽度。
- 回到开局选择后这一行收起。
- 截图落在 `docs/screenshots/scene-indicator-*.png`。

## 7. 旧存档与兼容

- 不要求重开：位置由服务端从现有 `current_scene` 派生。旧存档第一次拿到新
  客户端时立刻就有位置。
- 旧客户端收到多出来的 `scene`/`world_id` 字段不会报错（协议信封是宽松对象），
  只是不显示这一行。
- 新客户端遇到旧服务端（消息里没有 `scene`）显示“位置未知”而不是乱猜。
- 没有修改任何世界存档、没有改模组数据文件：`display_name` 优先取 `public_name`
  是可选机制，作者想给某个场景一个玩家可见名时再在模组里声明。猩红文档当前
  未声明，因此停尸房显示为它的场景名“密斯卡托尼克大学医学院”（同样是玩家可知
  的公开名称）。若要让该行显示“医学院地下停尸房”，只需给
  `scene_catalog.miskatonic_medical` 加一个 `"public_name": "医学院地下停尸房"`
  ——这是模组内容决定，且会改动模组文件修订号从而触发既有的整体静态刷新，
  因此本轮没有替作者做这个决定。

## 8. 本轮明确不做 / 仍有限制

- 共享场景模式下显示的是队伍位置；分队系统与“每个调查员自己的位置”不在本轮。
  将来分队后，玩家标题应显示自己控制的调查员所在场景（设计文档 7.1）。
- 不做演出同步：标题表示当前**已结算**位置，不跟随流式正文播放；将来若要与
  叙事同步，应携带明确的场景事件序号，而不是靠关键词或任意延时。
- 完整名称通过 `title` 提供（桌面悬停可读）。窄屏触控没有悬停，未做点击展开
  （首版约定不加入口），需要时可后续换成长按提示。
- 位置只反映世界状态，不校验“玩家是否知道这个名字”：`name`/`public_name`
  必须由模组作者保证是玩家可知名。作者若给秘密地点写了带剧透的场景名，应在
  该场景声明 `public_name`。
- `scene_state` 这类独立事件没有引入：现有状态的刷新时点（回合结束、读档、
  换世界、重连）已经覆盖全部验收场景，减少一条需要长期维护的广播链路。
