# 用户模型配置与上下文占用展示方案

日期：2026-09-07。状态：待实施；只定义方案，不代表代码已完成，不授权提交或部署。

## 1. 目标与强制交付边界

用户能自己选择叙述模型和裁决模型，并在需要时配置自己的模型服务；能看懂当前模型上下文用了多少、还剩多少，以及是否临近整理/容量边界。

用户已明确要求：**本地和云端同批交付同等功能，前端入口也必须完整暴露并接通，不能只完成 API。** 不把“改模型 ID”假装成完整的自带模型服务支持。

1. 本地单机/桌面与云端单人均支持自定义服务配置：服务商、Base URL、自己的 API Key、模型 ID、角色绑定、测试连接、保存应用和恢复默认。
2. 两端均展示主界面上下文摘要和详细统计；云端不能只保留预设模型选择，不能把 BYOK 或前端表单留到后续阶段。
3. 多人房间提供同一设置入口：房主有房间配置管理权限，成员/旁观者可看脱敏的生效模型与上下文。房主的个人服务配置通过服务器引用用于该房间，凭据不共享给成员；涉及付费和数据发送的确认见第 6 节。
4. 可以按步骤开发，但只有本地与云端完整链路都验收后才算交付完成。云端密钥隔离和出口保护是本次实现的前置条件，不是裁掉云端功能的理由。

本轮不做模型市场、自动挑“最便宜模型”、费用充值、多用户共享密钥、无校验网络代理、手动删除记忆按钮。自定义 Base URL 两端都提供，但受各自网络安全策略约束；功能对等不表示云服务器可以访问玩家电脑的 localhost。具体模型参数/能力在实现时按服务商官方资料核实，不在本计划中固化当前价格或窗口规格。

### 1.1 前后端一致性交付矩阵

| 功能 | 本地/桌面 | 云端单人（浏览器、桌面联机入口） | 多人房间 |
| --- | --- | --- | --- |
| 顶部模型设置入口、两个页签 | 完整可见 | 完整可见，不按 online 模式隐藏 | 所有人可见，按权限区分编辑/只读 |
| 服务商、URL、Key、模型 ID 表单 | 可配置 | 可配置，不能只有后台接口 | 房主可配置，成员看不到 Key |
| 叙述/裁决分别绑定 | 可编辑 | 可编辑 | 房主可编辑 |
| 测试、保存、恢复默认 | 全链路可用 | 全链路可用，刷新后保留账号配置 | 房主可用，有独立房间作用域 |
| 主摘要、上下文详情、状态同步 | 可见 | 可见 | 可见脱敏统计 |

差异只允许来自权限、凭据存储、配置作用域和可达网络。被安全策略拒绝的地址需在同一个表单里解释，不能把整个功能隐藏。多人不具备权限时明确显示“仅房主可修改”，并由服务器复核，不能只靠 disabled 按钮。

## 3. 用户界面

保留现有暗色旧黄铜风格、字体和顶部“模型设置”入口，不需要新生成图片。采用两个页签：**模型配置 / 上下文**。现有叙述速度仍是本地显示偏好，不和后端模型配置混为一谈。

### 3.1 模型配置页

- 显示运行模式和配置作用域，如“本地默认”“当前冒险”“当前账号”；不能含糊写“已全局应用”。
- 普通用户默认只看到叙述模型、裁决模型两项；提供“跟随默认”“自定义”。叙述管正文与对话，裁决管结构化行动判断；骰点与状态结算仍由规则引擎负责。
- 两端都提供“平台/默认配置”和“自定义服务”。平台出资模型目录来自服务端授权列表，用户自己的服务则使用其配置的模型 ID；不混淆这两种权限。原 Flash/Pro 预设只在对应模型真实可用时显示，不按 label 猜模型能力。
- 两端“自定义服务”都展开：配置名称、服务类型、Base URL、API Key、模型 ID；两种角色可以共用一个服务配置，也可以分别选择。
- 高级项：上下文窗口、最大输出 token；标注来源“目录已核实 / 用户手动配置 / 旧配置默认”。未知窗口不偷偷填成已核实值。
- 操作：测试连接、保存配置、恢复默认。测试不自动执行；更换模型不是自动发起真实游戏回合。
- 保存结果明确为“配置已保存”“当前生效”“下回合生效”，三者区分。回合中编辑可以保存待生效版本，不切换正在进行的请求。
- 测试失败显示可读原因：认证失败、不可访问、模型不可用、工具调用不支持、超时等；不回显 SDK 原始错误或完整请求。
- 切换到更小窗口前做容量预检：超限就解释原因并阻止立即启用，不能悄悄截断事实、规则或历史以凑窗口。

“测试连接”分为低成本连通性检测和明确的能力探针。探针用固定无剧情内容测试流式/结构化工具调用，事前显示目标域名、测试内容类别及“可能消耗少量额度”；模型列表接口成功不能替代能力探针。不得因用户点测试就发送当前模组、存档或秘密上下文。

### 3.2 主界面上下文摘要

在聊天输入区附近或现有状态行放一个小按钮，不新增常驻大卡片，不挤占人物三卡片侧栏：

```text
叙述上下文 · 最近一次输入约 18,400 / 65,536 · 28%   [详情]
```

这些数字只是示例，不是模型规格。点击打开“上下文”页签。窄屏简写“上下文 28%”，详情必须说明对应角色、模型、回合、时间、真实值/估算以及窗口来源。

无调用时显示“暂无调用数据”；模型已换但尚未调用时显示“新模型尚未调用”，可以另列旧模型最近记录，不能拿旧分子除以新模型窗口。断线或读档后标旧数据/清空，不能继续伪装实时。

### 3.3 上下文详情

- 角色切换：叙述、裁决；高级列表包括真实存在的战斗、审计、摘要、一致性重写等调用角色，不虚构不存在的独立模型。
- 总览：最近一次调用输入 token、窗口上限、输入占用比例、该次请求输出预留、估算剩余输入空间、更新时刻。
- 显示来源：服务商返回真实 usage；没有 usage 时用本地估算；两者都没有显示未知，不能显示 0。
- 分区估算：系统与规则、历史/摘要、当前行动与权威状态、工具 schema、检索内容；暂时无法可靠细分就保留现有 system/history/tool_schema 三类。
- 分区必须互斥；Lorebook 若已算进 system，不得重复相加。分区是估算，不强凑真实 usage 总数；不允许从数字详情展开隐藏正文或 NPC 秘密。
- 最近回合调用列表独立展示输入/输出/缓存命中（仅当提供方返回）。该回合所有调用 token 总和可作“回合用量”，不能叫“上下文占用”。
- 压缩状态只有在后端确实提供事件时才显示“整理中/已整理/失败”；没有事件就只显示容量提示，不宣称“已经压缩”。不新增清空历史或擅自变更压缩策略。

## 4. 数字口径：先定合同，再画进度条

每次实际请求记录以下公开元数据；以下字段为建议新增合同，不声称当前都存在：

```text
world_id / turn_id / call_id / call_role / timestamp
config_revision / provider_profile_id（不可推导凭据） / model_id
input_tokens / input_source = provider | estimate | unknown
output_tokens（请求后有则显示）
window_tokens / window_source = catalog | manual | legacy_default | unknown
reserved_output_tokens / target_tokens / hard_input_limit
context_sections（互斥估算，可选） / compaction_event（可选）
```

- 请求前采集的是完整模型请求的估算，包括真实装配的 messages、工具定义及可计量附件；附件无法估算需标注，不假装精确。
- 请求后若 usage 存在，以该次 `prompt_tokens` 作输入真实值，估算保留为分区参考。厂商字段差异由适配层归一化。
- `输入占用率 = input_tokens / window_tokens`；不是 `(输入 + 实际输出) / 窗口`，也不是整个存档总 token / 窗口。
- `可追加输入空间 ≈ max(0, window_tokens - reserved_output_tokens - input_tokens)`，名称明确是估计；输出预留取该请求实际生效配置，不取过时全局默认。
- 预警使用同一个容量计划：输入达到 hard 优先标红；否则达到 target 标“接近整理阈值”；其他正常。所有阈值与计数必须来自同一次请求的配置版本。
- 窗口未知时不显示百分比与剩余量。手动窗口显示“按配置估算”，不能视为服务商承诺。
- 缓存命中的输入仍占上下文窗口，不从占用分子减掉；缓存可能改变计费，但本轮不做费用承诺。
- 每个调用有独立快照；多轮工具调用通常输入大小不同，不将各轮输入累加为最后一次上下文。主摘要默认最近叙述调用，若本回合没有叙述调用，标明数据来自上一回合。

## 5. 模型配置与路由架构

建议新增独立配置服务和能力描述，避免继续把逻辑塞进已接近行数上限的 `registry.py`。

```text
用户设置 → 作用域与权限校验 → 配置版本 → 下一回合冻结
                                            ↓
角色路由 → 服务配置 / secret_ref → 对应 client → 请求能力适配
                                            ↓
                                    数字诊断 → 脱敏投影 → UI
```

- 非密钥配置：`profile_id / owner_scope / provider_kind / base_url / models / capabilities / revision`。
- 模型绑定：角色 → profile + model ID + 经校验窗口/输出配置。高级用户不是直接编辑整个 system prompt。
- 作用域建议：用户默认 → 当前冒险显式覆盖；多人房间使用房主明确选择的独立房间绑定，成员个人默认配置不覆盖房间。回合记录持久化实际模型和配置版本，不存密钥。读旧存档不恢复旧密钥、不改写历史模型标签。
- 本地旧 `.env.json` 兼容读取与迁移，不能抹掉凭据；在线按账号/冒险隔离，不许普通用户的修改写入进程全局 `.env.json` 或影响其他玩家。
- 一回合冻结所有角色绑定和能力配置；重试、工具续写、一致性重写使用冻结配置。记录发生的失败/回退，不能静默把请求发送到另一个服务商。
- 服务适配处理流式、tool calling、structured output、thinking 参数等差异；不能把当前特定服务的 `extra_body` 无条件发给所有“兼容接口”。能力不足时拒绝用作裁决模型，不自动关闭确定性闸门。
- client 按安全配置版本复用/失效，密钥更新后淘汰旧 client；禁止多个用户共享可变的全局 client 路由。
- 恢复默认只解除用户覆盖，不删除存档、不改变游戏事实、不泄漏服务器默认密钥。

## 6. 同步交付的安全边界

### 6.1 共用与本地约束

- 前端输入密钥仅在提交时传给可信后端；不得存入 localStorage、Zustand 持久化、URL、聊天、日志或回合记录。提交成功清空输入；读设置只返回“已配置”，默认不提供完整密钥回显。
- 本地优先系统凭据库；不可用时仅在用户明确选择后落本地受限文件，说明安全边界，排除 Git、打包资源和存档导出。浏览器不直连模型服务，不打包密钥。
- 本地设置修改/测试接口必须做来源、认证或本地令牌校验，不能因为服务绑定 localhost 就允许任意网页改配置、偷用额度。
- 本地自定义远程服务默认 HTTPS；本机 HTTP 推理服务作为明确的本地选项，显示数据发送位置。自定义地址禁止 userinfo/内嵌凭据；重定向与目标地址要复核，凭据不能转发到其他域名。
- 在线平台模式只开放运营者许可的模型与资源上限，用户不能通过提交任意 model ID 使用隐藏高价模型。控制测试频率、超时、最大输出和并发。

### 6.2 云端自带 Key（本次必做）

- 云端提供服务商预设与自定义 HTTPS Base URL 输入；出站网关对保存/测试/实际调用统一实施目标校验。校验所有 DNS 结果、IPv4/IPv6、端口、重定向与实际连接地址，防 DNS 重绑定和 SSRF，拒绝环回、私网、链路本地、云元数据等目标。平台内部可信服务由管理员独立配置，不复用用户输入路径。若部署要求域名白名单，前端显示被拒原因与管理员审批路径，不能静默移除自定义入口。
- 密钥按账号加密存储，主密钥独立于数据库和存档；读取/修改/删除校验所有权。日志与错误统一脱敏，认证 Header 不入审计正文。
- 明确告知故事、角色、模组上下文会发送给用户选择的服务商及额度归属；保存配置本身不表示同意自动发送全部历史进行测试。
- 多人房间默认由房主明确选择并确认使用自己的配置/额度，其他成员不能被暗中代扣。进入或更换服务商时向参与者展示故事数据发送目的地；未获得必要确认前不向新目的地发送房间上下文。成员仅看服务商/模型和脱敏用量，不看 Key、secret_ref 或个人 profile 管理数据。房主转移不自动转移密钥；原配置失去授权时暂停新调用并要求新房主重新绑定，不静默回退到平台付费模型。

## 7. 实施顺序与验收

1. 路由调查与基线：列出现有模式的读写路径、角色调用点、诊断采集点，保存当前测试基线；保护已有脏工作区。
2. 先完成上下文数字合同、按模型容量计划和脱敏投影，再画占用条；保留旧诊断协议兼容。
3. 同时完成本地与云端配置作用域、服务适配、凭据存储、出口安全和回合冻结；补账号/房间权限和 client 隔离测试。
4. 扩展共用设置面板与轻量摘要，接通本地和云端的读写/测试/诊断传输；处理保存/测试/断线/未知数据/切模型状态。不要保留 `mode === local` 的功能隐藏；能力字段只表达真实权限和安全限制。沿用 UI token，不必生图。
5. 分别从本地模式和云端模式的真实前端验证两个可用配置的切换、两种角色绑定、实际 usage 展示、刷新后持久化及超时/工具不兼容处理；固定低成本探针和完整游戏调用分开记录。云端模式可在隔离本地云端栈/授权 Pi staging 验证，不触碰生产。
6. 按第 1.1 节逐项提供两端证据；多人另外验证房主编辑、成员只读、付费/数据确认与房主转移。任一模式只有 API 或只有表单未接通，都不能标记整体完成。

必测：

- 本地浏览器、桌面本地、云端单人浏览器、桌面联机入口都能找到完整表单与上下文；从 UI 操作完成测试→保存→新回合→usage→刷新回读，禁止只用 curl/API 测试替代。
- 用户 A 改配置不影响用户 B；房主能改自己房间的绑定，普通成员/旁观者不能改；跨账号读取 profile/secret 拒绝。房间内角色变化后前后端权限同步更新。
- 当前回合中修改后，剩余调用仍使用旧版本，下回合才用新版本；失败时保留可用配置。
- 两模型不同窗口、输出预留、未知窗口、usage 缺失、空数据、缓存命中、重复事件、断线、切世界、读旧档、切模型尚无新调用，数值口径正确。
- 估算分区不重复统计，回合累计 token 不冒充窗口占用；不得泄漏 Lorebook 条目文本、名称、命中词或其他幕后信息给普通玩家。
- API Key 不进入 DOM 回显、持久化前端状态、日志、存档、诊断、导出或构建产物；测试连接不发送故事上下文。
- 本地与云端各提供 1280/939/640/390 宽度截图：模型表单和上下文入口均可见；主摘要不挤压发送按钮，设置弹窗可滚动，输入不溢出，按钮无竖排字，有焦点与禁用态。
- 后端 pytest、Ruff、架构门禁；前端组件测试、构建、E2E。按 `ui-button-check` 验收新控件；若改变模型装配/规则相关链路，按 `scarlet-playthrough-check` 跑最新代码完整真机主线。
