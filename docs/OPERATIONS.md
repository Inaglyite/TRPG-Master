# 运维、安全与发布

现行入口，整理于 2026-09-16。详细配置、命令、备份和恢复演练见[操作参考](reference/DEPLOYMENT.md)。仓库模板不代表主机已经采用相同配置；本文不授予任何生产操作权限。

## 1. 环境边界

| 环境 | 用途 | 限制 |
|---|---|---|
| 本地隔离运行目录/数据库 | 单元、集成、E2E、获准真实模型验收 | 不读写真实玩家存档，不继承生产 DB URL |
| Raspberry Pi staging | 默认预发布验证 | 本地先通过；地址与 SSH 可达性现场确认 |
| Azure staging | 明确需要外网时的预发布 | 与生产同机，须另行确认，数据库/凭据/目录隔离 |
| `https://trpggame.xyz` | 正式服务 | 不用于测试、冒烟账号或试改，只允许明确确认的正式发布动作 |

当前房间与 Agent 调度存在进程内所有权，保持单 worker 部署；不能通过增加 worker 或多副本绕过容量规划。当前线上版本、注册开关、证书、防火墙及恢复能力须由授权维护者核实，不从历史报告推断。

## 2. 模型与凭据

- 云端采用用户/世界 BYOK 绑定；成员参与房间不等于必须各自提供 Key，也不代表平台提供免费额度。具体费用归属以实际有效绑定为准。
- human 新模式不要求模型；agent/assisted 缺绑定应阻断或暂停，不回退平台 Key。
- 密码是 Argon2 慢哈希，不应改成可逆加密。模型 Key 因调用需要可解密，云端使用 Fernet；不能宣传成服务端无法读取的端到端加密。
- 主密钥与数据库备份须有独立的权限、保管和恢复安排。删除本应用绑定不等于吊销供应商 Key。
- 检查 URL 校验、DNS/固定连接、重定向/代理、来源与 Session 权限；仅有加密不构成完整安全验收。
- 本地 `.env.json` 等配置可能含明文机密，不打包、不提交、不打印；备份也按敏感资料保护。
- 2026-09-08 初审记录中的风险是历史发现，不自动等于当前漏洞或已修复；待核查项见 STATUS。

## 3. 发布门禁

1. 明确候选提交与范围：legacy/structured、human/Agent、本地/云端分别有哪些能力。
2. 本地与最终代码对应的 quality 通过；CI 红不能只用“本地绿”豁免。
3. 完成获准的真实玩法验证，注明模型与预算；未覆盖的新模式不能借旧主线成绩宣称完成。
4. staging 验证迁移、前后端版本、权限、恢复与目标使用流程；备份恢复在隔离库验证。
5. 用户确认具体正式发布版本；合并/push master 后 quality 绿，再人工触发 `deploy-azure`。
6. 发布按批准的运维流程确认激活与回滚状态，不临时在正式站点创建测试世界。

实验分支 push 仅备份开发成果，不等于发布授权。测试授权不等于自动消费无限额度或自动部署。

## 4. 激活入口与约定差异

当前仓库 `.github/workflows/deploy-azure.yml` 已调用 root-owned 固定入口 `/usr/local/sbin/trpg-activate-release`，安装资产在 `deploy/`。它不应接受任意脚本路径。

根 AGENTS.md 仍记录旧激活步骤的 sudo 限制。安全要求继续有效：禁止给部署用户可写的临时脚本授予 NOPASSWD，禁止 `sudo -S`、保存密码或 expect 绕过。发布前由授权维护者确认固定入口、installer、目录权限和最小 sudoers 在主机上实际安装；不能因仓库有代码就认定主机已具备。未确认时暂停激活，文档整理不自行修改 AGENTS 权限约定。

## 5. 数据迁移、备份与回滚

- Alembic 关系表迁移与世界 JSON schema 迁移是两条链；旧桌面无版本库还有 PyInstaller 接管逻辑。新增表/列必须覆盖三者相关边界。
- `runtime`、用户模组、数据库、Key 和日志与 release 目录分离。
- 加密备份能解密不等于恢复可用；隔离恢复需核对账号、成员、世界、请求/记忆、存档与 BYOK 解密。
- 数据库 dump 和运行目录归档不是天然同一事务快照；需要一致恢复点时安排明确静默写入窗口。
- 回滚代码不等于撤销迁移。发布前写明数据库前向兼容/恢复方案、可接受停机与数据损失边界，不直接删除或降级生产数据。
- 读档/分支是玩法能力，不能代替数据库灾备。

## 6. 运行检查与事故处理

详细命令在操作参考中，仅在相应授权环境执行：健康/就绪、TLS/WSS、权限与来源、实际监听和防火墙、登录与模型限流、运行目录权限、备份新鲜度、日志脱敏、磁盘/内存和模型延迟。

故障先保留版本、时间、请求/命令 ID 与脱敏诊断，再定位；不得为了调查导出完整 Key、Cookie、生产数据库或玩家剧情到第三方。紧急账号/注册/SSH 改动也须有恢复入口与明确权限，不能“顺手关闭 22”造成运维锁死。

正式上线是否具备条件，只根据[当前状态](STATUS.md)和指定候选证据判断，不根据旧报告的“全部完成”。
