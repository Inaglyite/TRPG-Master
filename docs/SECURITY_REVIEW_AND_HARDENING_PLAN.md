日期：2026-09-08。用途：后续实现任务与验收依据；本轮不修改业务实现、不发布。

## 1. 结论与证据边界

需要将安全作为下一阶段专项，而不只是增加一个“加密函数”。密码、API Key、登录会话、模型出站请求、浏览器来源和备份必须一起治理。

- 密码已使用 Argon2id，实测参数为 64 MiB、迭代 3、并行度 2；不是明文保存，也不应改成可逆加密。
- 会话随机令牌在数据库保存 SHA-256 摘要；账号模式 Cookie 设置 HttpOnly、Secure、SameSite=Lax。
- 工作区新增的云端 BYOK（用户自带 API Key）已用 Fernet 加密入库，返回配置不包含原始 Key。但本地配置仍以明文保存，且密钥生命周期、出站请求边界存在缺口。
- 没有证据表明已经发生入侵或用户 API Key 泄露；这不等于完成安全认证。后续核查所用的管理员 SSH 密码曾被粘贴到聊天，应尽快更换，本文不记录凭据内容。

**版本与环境限制：**审查时本地 HEAD 为 `2875f84`，BYOK 相关文件包含大量未提交改动。首次 SSH 认证失败；用户随后提供登录凭据，已完成 SSH 只读核查并退出。正式服务进程工作目录和 current 均指向 `19c27a56734a910b63767599fa4d7aeda343ab65`（本地 Git 记录日期为 2026-08-14）。线上 `src/auth.py`、`src/auth_http.py`、`server.py` 三个文件的 SHA-256 与该提交逐一相同；未作全发布目录或前端构建校验。线上不存在新增 BYOK 的四个模块文件，因此以下“新增 BYOK”问题属于新版本发布前风险，不是已证实的线上漏洞。正式站点未进行扫描、接口测试、测试账号登录或任何配置/服务变更。只读取安全配置白名单字段和元数据，未读取用户数据库、应用密钥或完整环境变量内容。

## 3. 按优先级处理的发现

这里的 P1 表示建议作为对应功能的发布阻断项，不表示已验证远程入侵；P2 为紧随其后的加固。

### S01 / P1：更换服务地址仍沿用旧 Key（新增 BYOK，离线反例确认）

`src/ai/model/route_service.py:parse_role_binding` 在新表单 Key 为空时，直接填入 `existing.api_key`，未判断服务地址是否变化。随后保存、连接测试或实际调用可能把旧供应商 Key 发送给新地址。

这是凭据目的地绑定缺失，不等同于已经证明其他账号能窃取 Key。反例只使用虚构密钥和模拟 DNS，无实际外发。

要求：凭据绑定规范化的服务端点及服务类型；端点或服务类型变化，默认不得沿用旧 Key，要求重新填写。相同端点仅改模型可保留。界面明确显示实际目的地，后端独立强制，不能只靠前端确认框。规范化应处理默认端口、主机大小写和尾斜杠，避免无意义变化误伤。共享域名下路径也可能区分租户，不能只比较主机名。

### S02 / P1：出站校验未绑定实际连接，且漏拦多播（新增 BYOK）

`egress_guard.py` 校验 DNS 返回的地址，但 `route_service.py` 创建 HTTP 客户端后，连接仍由客户端按主机名解析；校验得到的地址未用于约束连接。存在 DNS 重绑定/校验与使用不一致的结构性缺口。HTTPS 校验证书能缓解部分攻击，但不能替代网络出站边界；本轮未构造实际内网访问或证明数据可被读取。

另外，`ip.is_global` 不等于可接受的公网单播地址。离线模拟 DNS 返回 `224.0.0.1` 时，校验确实放行，与模块注释声称拒绝多播不一致。

要求：使用受控出站代理或经过评审的连接层限制，确保实际连接 IP 属于本次批准集合，并保留正确的 TLS SNI、证书验证和 Host；补充 IPv4/IPv6 特殊地址分类及网络层内网、回环、链路本地、云元数据隔离。所有重试、新连接及连接测试走同一策略。不得通过关闭证书验证来实现 IP 固定。未完成前，云端任意地址 BYOK 不应视为通过安全验收。

本地允许用户主动配置私网推理；云端不能把自身私网当作玩家的本地模型地址。两端功能入口都保留，安全规则按运行环境区分。

### S03 / P1：本地 WebSocket 默认不校验来源（既有代码，离线反例确认）

`src/auth/service.py:validate_websocket_origin` 在非账号模式、`TRPG_ALLOWED_ORIGINS` 为空时不拒绝任意来源。模拟不可信网站 Origin 的调用通过。新增的本地模型配置和连接测试使这一边界更敏感。

尚未进行真实浏览器攻击复现；浏览器私网访问策略可能影响可利用性，不能据此声称已经拿到用户 Key。

要求：本地模式也使用明确的可信来源；桌面壳使用受控来源及每次启动的连接凭证，凭证通过可信启动/IPC 链路交付，不放在可跨站读取的公开接口。缺失/`null` Origin 不自动信任，不把“仅监听 localhost”视为身份认证。验证恶意网页不能读取设置、修改目的地或触发带 Key 的请求，同时保持正常桌面启动可用。

### S04 / P2：本地明文与主密钥生命周期不完整（新增 BYOK）

- `route_service.py:save_local_settings` 明确使用 `include_secrets=True` 写 JSON，虽然文件权限为 0600，仍是明文；与 `crypto_box.py` 的本地加密说明不一致。
- 云端主密钥可由环境注入，否则自动生成于 runtime 的 `config_master.key`；未见版本化轮换机制。
- 当前 runtime 备份打包包含这个文件。外层备份已有加密，并非裸奔；但掌握备份解密能力者可同时得到密文和应用解密密钥。
- 文件首次创建的 `os.open(...O_EXCL...)` 位于捕获 `FileExistsError` 的 try 外，多进程创建竞争未正确兜底，属于可靠性问题。

要求：本地优先使用操作系统凭据库；不可用时明确告知存储降级与保护边界，不伪称已加密。云端使用独立受控的主密钥注入/托管密钥服务，生产禁止静默生成替代主密钥。密文增加 key version 与格式版本，支持新写新密钥、旧密钥只读、迁移验证、回滚和最终退役。备份数据与主密钥恢复材料分权管理、分别保留，完成隔离恢复演练，不能只删除密钥备份导致灾后不可恢复。

### S05 / P2：浏览器与账号防护进一步收口（既有代码/模板）

- `server.py` 无条件启用允许 `null` 和 localhost 来源、携带凭据的 CORS 配置；应拆分桌面/本地/云端策略，云端使用精确可信来源。
- HTTP Origin 检查在受保护 API 分支内，公开登录/注册不走同一来源检查；补齐适配登录流程的 CSRF/Origin 防护。现有 SameSite 和 JSON 请求约束有缓解作用，不能仅凭此代码结构声称 CSRF 已可利用。
- 登录限流主要为进程内状态，键包含 IP 与用户名；补充有界存储、过期清理、按账号及来源组合限制，明确多进程/重启语义，避免依靠无限封号造成拒绝服务。
- 仓库 nginx 模板缺少 CSP、禁止 MIME 嗅探与嵌入限制等完整响应头策略。先本地检查兼容性，再配置 CSP；不要直接上线一条阻断游戏资源加载的策略。

## 5. 实施顺序与验收要求

### 阶段 A：凭据外发与来源边界

生产运维先按 4.2 排序；开发侧处理 S01、S02、S03。新增本地确定性回归，必须同时有拒绝和正常放行的对偶用例：

- 同端点改模型可沿用 Key；换端点/租户路径/服务类型不能静默沿用；保存、连接测试、叙事与裁决调用均覆盖。
- 模拟 DNS 校验后变化，实际连接仍不能触达禁用目标；IPv4/IPv6、混合 DNS、重定向、重试、多播均覆盖。
- 恶意 Origin、缺失 Origin、`null` 来源不能绕过本地连接授权；合法浏览器和桌面壳能够正常连接。
- 房主、成员、旁观者、其他账号、所有权转移、旧连接与旧回合分别验证，不能查看/使用无权使用的凭据。

### 阶段 B：凭据生命周期

处理 S04；维持密码 Argon2id，不设计可逆“密码加密”。Key 只能在调用所需时解密，不进入模型上下文、前端持久存储、存档导出和日志。服务端代用户调用必然需要使用明文 Key，不能宣传成服务器无法读取的端到端加密。

前端提供已配置状态、替换、删除、实际目的地、测试结果；不回显完整旧 Key。区分“删除本应用保存的 Key”与“在供应商处吊销 Key”，不能把删除配置伪称供应商凭据已失效。关闭弹窗/退出登录清除敏感表单，避免断线队列自动重放旧的 Key 操作。

验收包括旧明文配置的安全迁移、权限检查、错误主密钥、密文损坏、轮换中断、回滚、主密钥丢失后的明确阻断，以及备份恢复。不得通过静默切回平台 Key 掩盖解密错误并产生费用。

### 阶段 C：账号、运维与持续门禁

处理 S05 与正式环境清单；核查改密码/重置密码后的会话撤销、敏感配置操作的重新认证、默认模型的额度滥用与连接测试资源上限。加入依赖漏洞检查和秘密扫描，但不要把真实凭据上传到第三方扫描服务。

本地全部通过后在 Pi staging 验收；云端与本地前端都验证设置入口、保存、连接测试、失败状态和上下文展示，不能只测 API。正式发布仍需用户明确确认，不能自动部署；正式环境不作为测试对象。

## 7. 设计参考

密码采用专用慢哈希而非可逆加密，当前 Argon2id 参数高于所列最低基线；后续按服务器负载与登录并发校准。[OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)

自定义 URL 带来 SSRF 风险，需要考虑 DNS 解析变化及应用、网络两层控制；“保存时检查过”不能单独证明运行时安全。[OWASP SSRF Prevention](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)

凭据治理需要覆盖创建、存储、轮换、撤销与恢复，而非只有静态加密。[OWASP Secrets Management](https://cheatsheetseries.owasp.org/cheatsheets/Secrets_Management_Cheat_Sheet.html)

SSH 支持公钥认证，配置文件片段的优先级会影响最终认证方式；修改前应验证配置并保持可用的管理入口。[Ubuntu OpenSSH server](https://ubuntu.com/server/docs/how-to/security/openssh-server/)
