# S3「明确出发」失败取证（交给后端修，前端不替模型决定）

来源：`docs/evidence/transition_real_model/trace_acceptance_frozen.json`
（冻结版代码 `75516a4+dirty`，逐文件 sha256 见报告；模型 `deepseek-flash`，BYOK 生效预算 32768；
隔离测试世界，真实猩红文档模组）。

## 1. 现象

S3 玩家说「那麻烦你联系一下，我现在过去。」→ **没有移动**（`miskatonic_university` 不变），
请求被挂成 `awaiting_player`，主持改为**澄清目的地**（“是去哪儿？我这串钥匙只认两扇门：
查尔斯的办公室，和他那间小屋。”）。判定 FAIL（需求允许「歧义时问一次」，但「承接已约定目的地」没做到）。

## 2. 当次请求的输入（逐项核查）

S3 是这一轮里**第一次**拿到模型的 `user` 上下文（逐字取自轨迹）：

| 核查项 | 结果 | 证据 |
|---|---|---|
| 是否包含已讨论目的地及**稳定 ID** | **包含，但没有任何绑定** | `snapshot.destinations = [{"id":"miskatonic_medical","name":"密斯卡托尼克大学医学院"}, {"id":"wright_office","name":"莱特的办公室"}]`；`snapshot.scene = {"id":"miskatonic_university","name":"密斯卡托尼克大学"}` |
| 最新玩家回应是否关联到正确待办 | **没有待办可关联** | `pending_requests` 只有本次触发（`trace-3`, `queued`, action=freeform「那麻烦你联系一下，我现在过去。」）；`trigger_request_id=trace-3` 正确；但 S1 请求已是 `declined`、S2 已是 `completed`，**没有跨回合保留的「已讨论目标/未执行行动」** |
| 当前场景与目标场景是否混淆 | **无混淆，但无处安放** | 当前场景是大学；两个候选目的地都在列表里；「过去」到底指哪一个，上下文里没有任何权威字段可读 |
| 是否有互相冲突的上下文 | **有** | 最近 6 条公开对话（layer 3）刚刚说过：①「遗体在鉴定完成后就该移交给家属或殡葬方了…**这不在校方能安排的范围内，我这把钥匙也帮不上忙**」；②「查尔斯不是死在医院里的…**我这间屋里也没有这么一位『值班医生』能跟你们对上号**」。而结构化层仍把 `医学院` 列为已知目的地，且没有任何命令把这两句话落成事实/限制 |

## 3. 定位：失败在「输入/上下文组装」，不是协议也不是执行

- 不是执行层：S3 的 `command_attempts` 里没有任何 `move_party` 被提交或被拒（主持根本没打算移动）。
- 不是协议层：`destinations` 与 `scene` 的稳定 ID 都在，帧与 schema 校验全过。
- 不是「历史被截断」：`truncated_recent_messages = 0`、6 条最近对话完整送达。
  **但「历史完整」不等于「关键上下文完整」**——关键上下文（已讨论/已约定的目的地及其 ID、
  双方刚确认过的限制）**根本没有以结构化形式存在**，只能靠模型从自由文本里重新推断，
  而那段文本恰恰是模糊且自相矛盾的。
- 结论：需要补的是**第 2 层「当前交互状态」**（已讨论的目标 + 稳定 ID、尚未执行的行动、
  已提醒过什么、在等谁回应）并且**在请求终态后仍然保留**（本轮 `declined`/`completed` 之后
  这层信息就消失了）。

## 4. 建议后端（Kimi）在上下文组装里补的东西（不涉及任何前端关键词规则）

1. **会话级的「已讨论/已约定目标」记录**：`{target_id（稳定 ID）, kind(scene|npc|clue|item), label,
   讨论轮次, 是否已约定, 已知限制}`，随世界状态持久化；请求进入 `declined`/`completed` 后**不清除**。
2. **上下文里显式给出「本次玩家回应 → 关联到哪个未执行行动/已讨论目标」的候选绑定**，
   没有可绑定时明确给出「无」——避免让模型自己从自由文本里猜。
3. **冲突提示**：当主持叙事里出现过「某目的地不可达/不成立」这类与权威状态不一致的表述时，
   在上下文中标注为「主持叙事中的说法（未落成事实）」与「权威状态」的差异，避免模型二者混用。
   （这正是 §7 里「传闻 vs 事实」的边界问题。）
4. 保持现有不变量：待办不是执行授权；不新增关键词判断器；是否移动仍由主持命令决定。

## 5. 前端本轮**不**做的事

- 不根据玩家文本里的「去/过去/继续/取消」替主持决定出发（本轮不新增任何文本解释器）。
- 不把「S3 失败」用前端规则掩盖（例如自动选中最近提到的目的地）。

## 6. S6 用例重设计（原用例前提错误）

原 S6「现在就出发去莱特的办公室」在 S4 已经把队伍带到 `wright_office` 之后执行，等于**原地移动**，
却期望 `scene_changed`——这是我的用例缺陷，不是产品缺陷。

重设计后的前提要求（已写进工具）：

- 起点**不同于**目标场景（`scene_before != target`）；
- 目标是 `snapshot.destinations` 里的**已知可达**目的地；
- 该世界没有额外障碍（无检定、无未告知条件）；
- 判定规则改为：**若起点已等于目标，则该用例记为 `INAPPLICABLE`（既不算通过也不算失败）**，
  并且单独用「出发前先确认起点 ≠ 目标」的前提断言把这种情况挡在用例设计阶段。
