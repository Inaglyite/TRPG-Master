# 调查员侧栏三卡片重构计划

日期：2026-09-07。状态：待实施；本文不是完成报告，不授权提交或部署。

配套素材提示词：[INVESTIGATOR_PANEL_UI_PROMPTS.md](./INVESTIGATOR_PANEL_UI_PROMPTS.md)。

## 1. 用户目标与本轮范围

将游戏中的人物状态栏拆为三张独立卡片，按 **人物状态 → 线索 → 道具** 排列。

- 人物状态卡：身份、HP、SAN、人物状态；详细属性可展开收起。
- 线索卡：分类查看、数量、线索详情展开收起，每条线索有明确的“出示”按钮。
- 道具卡：随身物品独立展示，每项有明确的“使用”按钮。
- 三张卡片自身可分别折叠；折叠、查看、筛选不产生游戏回合。
- “出示／使用”是玩家行动入口，不是前端修改游戏状态的快捷方式。

保留现有聊天叙事、骰子、NPC 气泡、handout、存档与调查笔记。此次不是重做开局角色选择，也不是新增背包装备系统、证据推理图或道具交易系统。

默认决策：继续使用右侧栏，不改成三个常驻悬浮窗口；窄屏改为抽屉，同一套组件同时服务桌面与窄屏。

## 3. 视觉方案与布局

### 3.1 风格

1920 年代调查档案、深棕黑底、旧黄铜薄边、克制的纸纤维质感。延续已有顶部图标与聊天区的风格，不能变成现代数据看板或金色花框堆叠。

视觉辨识点：三张卡片像同一套便携调查档案的三个页签；只在卡片左上角设置小型材质徽记，其他边框保持轻薄。内容为主，纹理与装饰不能压住文字。

| Token | 值 / 用法 |
| --- | --- |
| 页面底色 | 复用 `--bg: #14100c` |
| 卡片底色 | 复用 `--bg2: #1e1812` |
| 正文 | 复用 `--text: #ddd0bc` |
| 黄铜强调 | 复用 `--gold: #c8a24e` |
| 边框 | 复用 `--border: #3a2f24` |
| SAN / 危险 | 复用现有蓝色、红色 token，不只靠颜色传递状态 |
| 字体 | 标题与正文沿用 `--font-display / --font`；数值用 `--font-mono`；不新增远程字体请求 |

正文建议 14px、行高 1.6；辅助信息不低于 12px；标题 16–18px；卡片间距 12px、内边距 14–16px。状态数字始终显示，进度条只是辅助。

### 3.2 桌面线框（不是整页重做）

```text
┌────────────────────── 现有顶部工具栏 ──────────────────────┐
│ 聊天 / 场景叙事主区域                  │ 人物状态      [收起] │
│                                       │ 头像 姓名 / 职业     │
│                                       │ HP 8/10  SAN 52/60  │
│                                       │ 伤势/症状  [详细属性]│
│                                       ├────────────────────┤
│                                       │ 线索 · 12     [收起]│
│                                       │ 全部 探案 事件 任务 人物│
│                                       │ ▾ 探案线索 · 6       │
│                                       │ 莱特的日记 [详情][出示]│
│                                       │ ▸ 事件线索 · 3       │
│                                       ├────────────────────┤
│                                       │ 道具 · 5      [收起]│
│                                       │ 银质徽章       [使用]│
│ 现有行动选项与输入框                   │ 手枪（6发）    [使用]│
└───────────────────────────────────────┴────────────────────┘
```

- ≥1200px：侧栏建议 340px，最大 360px，聊天保留可读宽度。
- 1000–1199px：侧栏 300px，卡片内部允许操作行下移，禁止挤压按钮。
- <1000px：沿用顶部入口打开右侧抽屉，宽 `min(380px, 100vw)`；939px 必须采用抽屉，不硬挤聊天。
- ≤640px：抽屉可占全宽，明确关闭按钮；底部避让 safe-area 与软键盘。打开行动编辑器时关闭侧栏抽屉，避免双重遮罩。
- 只有侧栏/抽屉外层滚动，避免卡片里再套三层滚动区；头部操作始终可达。
- 初始状态：人物状态、线索、道具卡展开；详细属性收起；线索在“全部”视图中仅首个非空分类展开，长条目正文默认收起。
- 卡片折叠后仍显示名字与 HP/SAN 摘要，或线索/道具数量。新增线索只标“新增”，不抢焦点、不强制展开、不滚动聊天。

## 4. 三张卡片的交互合同

### 4.1 人物状态卡

- 姓名、职业、头像（可用才显示）、HP/SAN 数值和进度条。
- 详细属性采用 disclosure；延用已有属性键，不硬编码只支持一个模组。
- 若公开角色数据已有 `conditions`，显示本地化症状标签；当前 `CharacterState` 未声明该字段，实施时先核对实际公开 payload。字段缺失就不显示，不从 HP/SAN 猜出昏迷、死亡、疯狂等状态。
- 若确有需要新增字段，必须是服务端已有事实的白名单公开投影，覆盖本地和在线两条推送/读档路径；不能泄漏未公开 NPC、线索或后台标记。
- 折叠状态下也能看到低 HP/SAN 的文本提醒，不设计前端“治疗”“恢复理智”按钮。

### 4.2 线索卡

- 筛选：全部、探案、事件、任务、人物；标签中文分别复用“探案线索／事件线索／任务线索／人物线索”。窄屏可换行，不压成竖排字。
- “全部”视图按分类分组，各组可收起；选定分类后只显示该分类列表，不再要求重复展开一层。
- 未知分类不能丢失：合并为“其他”组并计入总数。
- 每行展示公共名称/摘要、类型标记、可选图片缩略图、详情开关和“出示”。不要把 `TIER2` 原样作为主要面向玩家标签；只展示与玩家理解有关的已有信息。
- 现有 `ClueItem` 未必有标题：优先公共 asset label，否则从公开 `text` 第一行生成纯展示摘要；详情保留完整原文，不能让 LLM 额外编造标题事实。
- 详情开关和“出示”是兄弟按钮，不把 `<button>` 嵌套进 `<button>`。缩略图点击仍保留大图预览与键盘关闭。
- 展开/分类偏好仅属于 UI；按世界/时间线作用域记录。作用域键不可用时仅保留会话内状态，不拿角色名字当世界标识。切世界重置草稿，删去不存在的条目展开状态。
- 数据只来自玩家可见 `clues`，不能加载完整 `clue_catalog` 来补全“未知线索”。

### 4.3 道具卡

- 当前权威库存为字符串数组，保留原始标签，例如“手枪（6发）”。不要将显示层解析出的数量当作真实库存数据。
- 相同原始标签可聚合成一行显示“同名记录 ×N”，但不冒充堆叠数量；操作时再选择或说明对象。渲染键需区分重复条目，不以数组索引充当后端物品实例 ID。
- 每行“使用”按钮，长物品名换行、操作按钮不换行。空库存显示“暂无随身道具”。
- 不增加不存在的重量、品质、稀有度、耐久、装备槽或万能效果。
- 线索与物品可同时出现：线索是已知信息，库存是实际持有物；不能因为发现了文档线索就给背包新增文档。

## 5. “出示／使用”：编辑意图后提交一次行动

### 5.1 统一行动编辑器

点行内按钮打开轻量编辑器，不立刻发送、不推进时间。桌面为有焦点管理的小对话框；窄屏为底部面板或全屏对话框。支持 Escape、关闭和取消，取消不产生消息/回合。

“出示”编辑器：

1. 显示所选线索摘要与详情入口。
2. 必填“向谁出示/说明”（自由填写 NPC 名称；不自动选唯一 NPC，也不向全场/所有在线玩家广播）。
3. 可选“想询问什么”。
4. 显示可编辑的行动预览、明确“这是行动请求，结果由守秘人与规则裁决”。
5. “确认出示”提交；“取消”关闭。

出示的语义必须区分信息与实物：

- 所有已知线索都可从“出示”入口发起**说明线索**。只有记忆、口供、推理，或不确定是否持有原件时，默认预览为：`我向惠特克罗夫特说明我已知的线索：「……」，询问他对此的看法。` 不创造纸质笔记、照片副本、原件。
- 若服务端已有明确、公开的持有关系，或玩家在编辑器中明确选择并填写当前库存中的实物，可预览为：`我向惠特克罗夫特出示随身携带的「莱特的日记」，让他查看，不递交、不赠送、不消耗。` 后端仍须核验。
- 不用文本相似度把线索名称与物品强行绑定。没有权威关联时不要自动提供“出示原件”模式；玩家仍可在自然语言里说明意图，由已有裁决判断。
- `asset_url` 或 handout 图片存在，只代表 UI 有可查看素材，不证明调查员拿着该物品。

“使用”编辑器：

1. 显示库存原始标签。
2. 必填“如何使用”，可选“目标/对象”；提示例子使用通用措辞，不预告模组解法。
3. 行动预览如：`我尝试用「手电筒」照亮床底，检查是否有可见物品。` / `我尝试用「绷带（2份）」为自己包扎伤口。`
4. “确认使用”提交一次行动；按钮不可直接执行消耗、治疗、开锁、封印或开枪。
5. 消耗品是否消耗、耐用品是否仅使用、是否检定、战斗中是否可行动，全部沿用已有后端规则。不能把 inventory 的 `use` 工具直接当“一键实现物品效果”。

### 5.2 接入现有发送流程，而非新开一条写状态接口

V1 使用已有 `{type: "action", content: text}` 和 `sendAction`，不新增“直接出示/直接使用成功”的 WS 消息或 API，也不从浏览器调用内部工具。

- 编辑器维护独立草稿，不覆盖聊天框内尚未发送的玩家文本。
- 提交前重新读取当前角色/线索/物品和世界身份；物品消失、线索不存在、切换世界或角色后，阻止提交旧草稿并说明原因。
- 复用统一权限判断：已连接、允许输入、没有 pending 行动、没有待处理 decision/suggest/结局确认、在线模式轮到本人且有玩家权限。浏览查看与折叠仍可用。
- `sendAction` 当前返回 `void`，且调用方需要保证输入/连接状态；不可认为调用就意味着发送成功。允许将它以兼容方式改为返回“已接受发送/拒绝”结果，或抽取共享 guarded submit，所有旧调用继续正常工作。
- 连点、Enter 与点击同时触发只能发送一次；pending 立刻锁确认按钮。显示“已发送，等待裁决”，不能显示“已使用成功”。
- 断网不把动作无提示排队重发；拒绝/发送失败保留草稿并允许玩家主动重试，不能重发已有 pending 回合。
- 客户端不乐观扣道具、增线索、改 HP/SAN/时钟。只依据服务器后续权威推送更新卡片，复用已有行动气泡及回滚处理。
- 上述前端校验只是体验提示；恶意或过期客户端仍必须由现有服务器权限、持有状态、失能和裁决闸门拒绝。

如果实施中发现普通 `action` 流程无法安全表达这两类意图，先记录具体缺口和失败测试，再补最小兼容接口；不能临时扩展工具权限或让前端成为事实来源。

## 7. 实施阶段与交付物

1. **冻结范围和基线**：读取 AGENTS.md 与相关 skills；记录脏工作区，不覆盖 Kimi/Codex 先前改动。先运行相关现有测试，列出实际数据字段和发送权限。
2. **三卡片 UI**：先用现有素材/CSS 完成拆分、分类、展开、数量、空状态、长文本和窄屏；不等待新图片，不编造权威数据。
3. **行动编辑器**：接通出示/使用、预览、取消、一次发送、禁用原因、过期草稿；补单元和组件测试。
4. **状态同步与兼容**：检查新回合、读档、回滚、重连、切世界、在线旁观/非当前行动者；复测图片预览和原人物面板入口。
5. **视觉验收与素材替换**：按配套提示词接入最终资产，只替换装饰层；浏览器截图验证而非只审 CSS。
6. **本地真实交互验收**：从 UI 点出示已知信息、出示实际持有物、使用耐用品、使用消耗品，核对聊天输入和状态账。实机缺少模组物品时使用隔离测试世界，注明注入部分。
7. **交付**：改动摘要、测试结果、截图位置、真实模型报告、已知边界。未经用户明确要求不 commit/push，不激活 Pi，不部署生产。

如果第 3/4 阶段改到场景/发现/检定/战斗/SAN/结局逻辑，必须使用 `scarlet-playthrough-check` 跑最新代码完整主线；纯 UI 改动也至少完成真实出示/使用的定向验收，不能拿旧版主线报告代替新交互证据。

## 8. 验收清单（完成条件，不可用“按钮出现了”代替）

| 面 | 必测场景 / 通过标准 |
| --- | --- |
| 基本布局 | 三张独立卡片；状态、线索、道具不再混在同一正文块；无重复旧列表 |
| 折叠/筛选 | 三卡片独立折叠；五个筛选正常；未知分类进入“其他”；总数与筛选数可解释；切换不丢数据、不发送回合 |
| 数据边界 | 只显示已知线索和当前库存；读过原件但未取得时，不能自动出示原件或背包增物 |
| 真实操作 | 出示信息不产生实物转移；出示持有物不赠送；耐用品使用不消失；消耗品仅按实际结算扣减；失败不能显示成功 |
| 行动控制 | 空对象/空用法不提交；取消无动作；双击/Enter 只一次；断网/叙事中/确认门中/旁观/非本人回合不能绕过入口 |
| 状态更新 | 使用后物品与数量按服务端更新；HP/SAN、回滚、读档同步；切世界关闭旧草稿；旧图片/展开 ID 不串档 |
| 长内容 | 0/1/50 条线索、长名称、同名物品、缺失图片、所有分类为空；不得溢出或丢条目 |
| 无障碍 | 折叠用 button + aria-expanded/aria-controls；详情可键盘访问；弹窗焦点锁定、Escape、关闭后焦点返回；状态变化用适量 aria-live |
| 布局截图 | 1280×800、939×800、640×800、390×844；另测 939 宽 200% 缩放；不遮挡发送区，不横向溢出 |
