# 多人游戏使用说明

本文面向普通玩家和房主，介绍如何通过浏览器或 Electron 桌面版加入同一个权威服务器房间。
部署、数据库和服务器运维请分别阅读 [`DEPLOYMENT.md`](DEPLOYMENT.md) 与
[`DATABASE.md`](DATABASE.md)。

## 1. 上线前提与当前状态

多人模式必须使用服务器维护者提供的、浏览器信任的 `https://` 地址，例如
`https://trpg.example.com`。Electron 只接受不带路径、查询参数和片段的 HTTPS origin：

```text
正确：https://trpg.example.com
错误：http://trpg.example.com/game?room=1
```

当前 Azure 验收环境仍是 IP 地址加自签名证书，只用于受控测试；正式域名和受信任证书尚未完成。
普通玩家不应绕过浏览器证书警告，Electron 也会按设计拒绝不受信任的证书。服务器维护者完成正式
TLS 配置后，再把最终地址发给玩家。

单机和多人是两个独立入口：

- 单机模式连接本机服务，使用本地数据，不需要账号；
- 多人模式连接云端服务，账号、房间和存档都以服务器数据为准；
- 不要把单机服务端口直接暴露到公网，也不要期待单机存档自动出现在多人大厅。

## 2. 打开多人模式

### 当前桌面发行方式

- Linux 当前不提供 AppImage。请从源码目录执行 `bash start_desktop.sh`，再在启动页选择多人游戏。
- Windows 用户可使用维护者构建的 NSIS 安装版或便携版；维护者在 Windows PowerShell 中运行
  `powershell -ExecutionPolicy Bypass -File packaging/build_windows.ps1`，产物位于
  `frontend/release/`。
- Electron 只有在选择单机时才启动本地后端并要求配置本地模型 API Key。选择多人会直接加载云端
  HTTPS 应用，不启动本地后端，也不需要玩家在本机填写模型 API Key；模型配置由服务器维护者负责。

### 浏览器

1. 用最新版 Chrome 或 Edge 打开服务器维护者提供的 HTTPS 地址；当前自动化验收基于 Chromium，
   Firefox 尚未列入正式兼容性验收。
2. 在模式选择页点击“多人游戏”。
3. 浏览器版使用当前网站作为服务器，不需要另填地址。

### Electron 桌面版

1. 启动 TRPG Master。
2. 在“云端服务器”中填写维护者提供的完整 HTTPS origin。
3. 点击“多人游戏”。

如果 Electron 提示地址无效，确认地址以 `https://` 开头，且末尾没有 `/game` 等路径、`?` 参数或
`#` 片段。需要切回单机时，可从登录页或大厅返回模式选择。

## 3. 注册与登录

登录页提供“登录”和“注册”两个标签：

- 用户名为 3–40 位汉字、字母、数字、下划线或连字符；字母不区分大小写；
- 密码长度为 10–256 个字符；
- 如果显示“注册已关闭”，请联系服务器维护者创建账号，不要反复提交；
- 多次输错后可能暂时触发限流，请等待一段时间再试；
- 点击“退出登录”会撤销当前会话；登录过期时需要重新登录。

账号只代表服务器身份。进入某个房间还需要成为该房间的成员，不能通过猜测房间号访问他人的游戏。

## 4. 创建或加入房间

### 房主创建

1. 在“联机大厅”的“创建房间”区域填写可选房间名。
2. 选择模组和 2–4 人上限。
3. 点击“创建房间”。创建者自动成为房主。
4. 在房间页的“邀请”区域选择邀请角色、有效小时数和最多使用次数。
5. 点击“生成邀请码”，复制后通过可信渠道发给对应玩家。

邀请可以授予“玩家”或“旁观者”身份。邀请码等同于一张临时入场券，不要发到公开群；不用时由房主
在邀请列表中撤销。过期、撤销或用尽次数的邀请码不能继续加入。游戏开始后不能再用玩家邀请增加
参战玩家，但仍可邀请旁观者观看；需要新增玩家时，应在开局前完成加入、选角和准备。

### 成员加入

1. 登录后，在大厅的“邀请码加入”区域粘贴完整邀请码。
2. 点击“加入房间”。
3. 加入成功后，房间会出现在“我的房间”；以后可直接点击房间卡片进入。

“大厅”只是返回房间列表，不等同于退出房间。只有点击房间页底部的“退出房间”并确认，才会移除
自己的成员关系。

## 5. 角色、准备与开局

房间内有三种成员角色：

| 角色   | 能力                                                               |
| ------ | ------------------------------------------------------------------ |
| 房主   | 邀请和管理成员、指定或跳过行动者、开始游戏、管理共享存档、移交房主 |
| 玩家   | 选择调查员、准备，并在轮到自己时提交行动                           |
| 旁观者 | 查看房间和公开内容，不能选角、准备或提交行动                       |

开局前，每位房主或玩家都要：

1. 在“调查员”区域选择一名尚未被占用的默认调查员或模组调查员；
2. 点击“准备”；
3. 保持在线，等待其他玩家完成同样操作。

多人模式目前不读取玩家电脑上的 `profiles/player_profile.json` 或 `characters/custom/`，因此长期
角色和自定义角色不会出现在联机候选项中。这些资料仍只用于本地单机。

只有全体非旁观成员在线、已选角且已准备时，房主的“开始游戏”按钮才可用。按钮不可用时，页面底部
会列出谁离线、未准备或未选角。需要换角时应先“取消准备”，再释放当前调查员并重新选择；游戏已经
开始后不要依赖换角功能。

房主可以把成员改为玩家或旁观者、移除成员，也可以把房主身份移交给另一位成员。这些操作会影响
对方是否能行动、管理存档或继续留在房间，请先和队友确认。开局后可以把现有玩家降为旁观者，
对方会自动按新角色重连；不能再把旁观者提升为玩家，也不能把房主直接移交给旁观者。房主仍可在
已经参战的玩家之间移交。

## 6. 游戏中的行动顺序

顶部房间条会显示“轮到你行动”或“等待某人行动”。只有当前行动者可以点击剧情选项或在输入框提交
自由行动；其他玩家的输入会暂时禁用。这样可保证同一个房间只有一条权威的守秘人历史，不会因两人
同时提交而产生两套世界状态。

房主可以在房间页点击“指定行动”，或在顶部房间条点击“跳过行动者”。普通玩家不能代替当前行动者
提交内容。网络卡顿时不要连续重复点击；客户端会使用稳定的行动标识，服务器也会拒绝重复或并发执行。

所有成员看到相同的公开叙事、检定和公开线索，但每人看到的角色状态会绑定到自己的调查员。

## 7. 私密内容与调查笔记

“仅你可见”的线索、决定、回复和调查笔记会按登录账号单独发送和恢复，其他玩家（包括房主）不应从
正常接口看到这些内容。刷新或重连后，服务器会重新下发当前账号可见的私密状态。

仍需把邀请码、私密线索和个人笔记当作敏感内容：

- 不要把带有私密面板的截图共享给其他玩家；
- 不要共用账号或浏览器会话；
- 在公共电脑上游玩后点击“退出登录”；
- 发现别人的私密内容时，停止操作并联系服务器维护者。

## 8. 存档与恢复

多人房间的存档属于整个共享世界。当前协议会把存档列表的摘要元数据发送给房间连接，因此普通
成员可能在客户端状态或网络响应中看到槽位名称、场景、时间等摘要；列表响应不包含完整世界快照
或消息历史。
只有当前房主能执行“快速存档”、新建、读取、重命名、删除和恢复，前端也只向房主显示这些操作
按钮，服务端会再次校验房主权限：

- 每个完整守秘人回合结束后会更新自动槽 `slot_000`；
- “快速存档”也会覆盖该自动槽；
- “存档管理”可以新建、读取、重命名和删除手动槽；
- 读取存档会改变整个房间的权威状态，不是只改变房主自己的画面。

房主读取或恢复前应先通知其他玩家。正在生成回合时尽量不要关闭全部客户端；如果必须离开，等待界面
完成当前回合或确认自动存档已更新。

## 9. 断线、刷新与重新进入

短暂断线时，界面会显示“已断开，重连中……”。通常按以下顺序处理：

1. 先等待自动重连，不要重复提交刚才的行动；
2. 长时间没有恢复时刷新浏览器，或重启 Electron；
3. 会话仍有效时，重新进入“我的房间”，客户端会恢复公开历史、自己的角色和私密内容；
4. 显示“登录已过期”时重新登录；
5. 仍然失败时确认服务器地址和网络，再联系维护者并提供错误文案与发生时间。

以重连后服务器下发的房间状态为准。不要用多个标签页控制同一账号的同一回合，以免自己难以判断哪
个页面是当前操作窗口。

## 10. 退出、移交与房间管理

- 普通玩家或旁观者可在房间页点击“退出房间”；退出后需要新的有效邀请码才能再次加入。
- 房主不能直接退出，必须先在成员列表把房主“移交”给另一位成员。
- 房主可以“移除”成员；被移除者会失去该房间权限。
- “返回游戏”关闭房间管理页，“大厅”返回房间列表，两者都不会退出房间。
- 当前版本没有供普通玩家使用的“关闭并删除房间”按钮；不要把离开房间误认为删除共享数据。

## 11. 常见问题

| 现象                                     | 处理方式                                                   |
| ---------------------------------------- | ---------------------------------------------------------- |
| Electron 提示服务器地址无效              | 使用维护者提供的裸 `https://` origin，去掉路径、参数和片段 |
| 浏览器出现证书警告，或 Electron 无法连接 | 不要绕过警告；联系维护者配置受信任证书                     |
| 显示“注册已关闭”                         | 联系维护者创建账号                                         |
| 显示“尝试过于频繁”                       | 停止重试，稍后再登录或注册                                 |
| 邀请无效、过期、已撤销或次数用完         | 请房主生成新的邀请码，并确认邀请角色                       |
| 开局后玩家邀请或角色提升被拒绝           | 进行中的房间不再增加玩家；可改用旁观者邀请，或新建房间     |
| 调查员显示“已被占用”                     | 选择其他调查员，或请占用者在开局前释放                     |
| 看不到本地长期角色或自定义角色             | 联机当前只支持默认/模组调查员；个人角色仅用于单机           |
| “开始游戏”不可用                         | 查看页面底部提示，确保全体玩家在线、选角并准备             |
| 输入框显示“等待某人行动”                 | 当前不是你的回合；等待行动者或请房主调整行动权             |
| 看不到存档按钮                           | 多人存读档只对房主开放                                     |
| 房主无法退出房间                         | 先把房主移交给另一位成员                                   |
| 刷新后暂时没有历史或私密线索             | 等待连接变为“已连接”；仍未恢复时重新登录并从大厅进入       |

如果问题可稳定复现，请记录客户端类型（浏览器或 Electron）、服务器地址、发生时间、界面错误文案和
操作顺序。不要在截图或日志中附带密码、登录 Cookie、API Key 或仍有效的邀请码。
